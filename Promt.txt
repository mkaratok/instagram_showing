3. Backend Katmanı (Server Routes)

Veritabanı olmadığı için Nuxt'ın sunucu rotalarını bir "Proxy" olarak kullanacağız. Bu, Token'ın tarayıcıda görünmesini engeller ve CORS hatalarını çözer. Ayrıca basit bir önbellekleme (Cache) stratejisi uygulayarak API limitlerini koruruz.

server/api/instagram.get.ts
TypeScript

import { defineEventHandler, getQuery } from 'h3'

const BASE_URL = 'https://graph.facebook.com/v19.0'

export default defineEventHandler(async (event) => {
  const config = useRuntimeConfig()
  const { fields } = getQuery(event)

  // Token veya ID yoksa hata fırlat
  if (!config.instagramAccessToken || !config.instagramUserId) {
    throw createError({
      statusCode: 500,
      statusMessage: 'Instagram API konfigürasyonu eksik.'
    })
  }

  // İstenen alanları belirle (Default değerler)
  const queryFields = fields || 'id,caption,media_type,media_url,thumbnail_url,permalink,timestamp,like_count,comments_count,children{media_url,media_type}'
  
  try {
    // 1. Profil Bilgilerini Çek
    const profileResponse = await $fetch(`${BASE_URL}/${config.instagramUserId}`, {
      params: {
        fields: 'name,username,profile_picture_url,biography,followers_count,follows_count,media_count',
        access_token: config.instagramAccessToken
      }
    })

    // 2. Medyaları Çek (Limit: 24 - Grid için ideal)
    const mediaResponse = await $fetch(`${BASE_URL}/${config.instagramUserId}/media`, {
      params: {
        fields: queryFields,
        access_token: config.instagramAccessToken,
        limit: 24
      }
    })

    // Stories (Hikayeler 24 saatliktir, API bazen boş dönebilir)
    // Not: Stories için 'instagram_manage_insights' izni gerekebilir.
    // Basitlik adına burada sadece media ve profil dönüyoruz.

    return {
      profile: profileResponse,
      posts: mediaResponse.data,
      // Cache kontrolü için header ekleyebiliriz (Nuxt route rules ile de yapılabilir)
    }

  } catch (error) {
    console.error('Instagram API Error:', error)
    throw createError({
      statusCode: 502,
      statusMessage: 'Instagram verisi alınamadı.'
    })
  }
})

Projenin Kritik Noktaları ve Senior Tavsiyeler

    Medya Çözünürlüğü: Instagram API'si orijinal medya URL'lerini verir ancak bunlar süreli (signed URL) olabilir. Bu yapıda görsel linkleri dinamik olarak API'den her istekte taze gelir. Eğer görseller kırılırsa, refresh mekanizması çalışmalıdır.

    Mesajlaşma (DM) Sınırlaması: Kullanıcı "Message me" butonuna bastığında API üzerinden mesaj attırmak için karmaşık webhook ve 24 saat kuralı gerektirir. DB olmayan bir yapıda en temiz çözüm, ig.me linki kullanarak kullanıcıyı doğrudan uygulamanın DM ekranına yönlendirmektir.

    Video/Reels: media_type === 'VIDEO' olduğunda thumbnail_url kullanılır, grid görünümünde performans için video hemen yüklenmez. Modal açıldığında video oynatılır.

    Performans: nuxt-img kullanımı görsellerin optimizasyonu için önemlidir. swr (stale-while-revalidate) veya cache kullanarak API istek sayısını düşürdüm.

    Güvenlik: Access Token hiçbir zaman istemciye (browser console) düşmez. Tüm iletişim /api/instagram üzerinden proxy edilir.
